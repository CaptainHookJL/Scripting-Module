The .old, .dat, .zip, .png and .bin examples are unrecognised by this name-based classifier. wc -l counts newline bytes, not records meaningful to a PNG. A nonempty file can have zero newline bytes. wc -c counts bytes and [ -s file ] checks byte size, so both are better for binary emptiness.

Removing quotes only from [ -z "$USERNAME" ] with empty input gives [ -z ], which Bash treats as a true one-argument test; it emits no error in this exact case. The worksheet implies an error, but an unquoted equality test with empty input can instead produce unary operator expected. Unquoted multiword values can produce too many arguments. Always quote expansions.

Using = (text comparison):
  not equal
Using -gt (numeric comparison):
  10 is greater than 9
Using \> (text ordering):

Exit code: 0
Text equality says 10 and 9 differ; numeric -gt says 10 is larger; lexical ordering compares first characters, so 10 sorts before 9.

==============================================

At least 10
Exit code: 0

Non-negative
Exit code: 0

A hidden carriage return makes true\r differ from true while often looking identical on screen. tr -d "\r" fixes this; configuration scripts normalize terminal CR bytes. Original order_bug matches >=0 first, swallowing the >=10 branch; the fixed version checks >=10 first.
