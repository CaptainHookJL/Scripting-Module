Layout and running the lab
==========================
Run all commands from lab09. The original worksheet is lab09.md in this folder. The worksheet names lab04-data and lab03-data; this checkout instead uses lab04 and root-level iocs.txt/users.csv. case and intel are unchanged copies of those sources. The 14 exercise scripts share lib/common.sh for input guards, grep status handling and one consistent extension/type policy. No collected script or evidence executable was run.
The scripts use for loops for file lists, indicators, attackers and running totals. Indicators are loaded into an array by line so that a future value containing spaces is preserved. Exit 1 means unexpected arguments; exit 2 indicates an input or processing error. A grep no-match result is handled separately from a read/search failure.

ELF magic bytes are 0x7f 45 4c 46 (DEL followed by E L F). unknown class 154 is not a valid ELF32/ELF64 class and suggests malformed or synthetic/corrupted content, not a proven working program. It was inspected without execution.
Final extension policy: PNG for .png; Zip for .zip; text for .txt/.md/.log; shell script for .sh; Python for .py; empty for a zero-byte .bin (otherwise generic data); generic data for .dat. The .bin/.dat policy is an exercise convention: these broad extensions do not inherently forbid executable data. The ELF signature and invalid header, rather than the generic suffix alone, justify review.
The final !! files are suspicious.dat (ELF versus generic data), report.py and scan.py (file detects ASCII text rather than Python). The tiny Python examples have no shebang and are valid source despite file not identifying their language, so these are heuristic false positives. check.sh matches shell-script content, regardless of its execution permission. Final policy covers every extension in the fixtures, leaving no ?? results.
